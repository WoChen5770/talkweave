## Why

操作者希望复用 NAS 已有的 MySQL 与 Redis，并明确不需要保留当前 SQLite 中的账号和聊天历史。现有历史查询先加载整个会话再裁剪，旧单用户链路与联调工具增加维护负担，模型请求也缺少当前时间；本次将存储替换、近期历史缓存、时间上下文与旧路径退役作为一项可独立验收的改造。

## What Changes

- **BREAKING**：MySQL 成为唯一生产业务存储，统一承载管理员、用户、绑定、会话、入站事件、回复状态、模型配置、用量和审计；采用全新专用 schema，不导入 SQLite、不维护双写或运行时回退。新部署重新初始化管理员、配置模型和扫码绑定，不自动删除或修改任何旧数据库和登录材料。
- 使用连接池、短事务与数据库并发约束替换单连接全局串行；历史查询先过滤模型成功且确认送达的完整问答，再读取当前消息之前的最近 N 轮。保留按用户串行、跨用户有界并发、持久去重、授权代次及不确定外部操作不重放。
- 保留本 change 已执行的 MySQL V001 脚本，增加 V002 的会话分页序号及索引；只升级精确识别且取得独占运行锁的 V1 布局，保留已有表、业务数据与现有数字分页接口。升级中断拒绝开放业务，不以删表重建或改写旧脚本修复。
- 接入现有 Redis 缓存活跃会话的有界历史窗口，首次回源、确认送达提交后增量更新；校验授权、历史版本、消息序号与窗口完整性。Redis 失效可有界降级至 MySQL，缓存不承担权限、持久状态或模型提供商输入缓存的职责。
- 每轮模型请求注入可信的当前日期、时间、星期、UTC 偏移和可配置时区，默认 `Asia/Shanghai`。时间在请求组装时采样、同轮重试保持快照，计入上下文预算，不改变固定系统前缀、不写回用户原文、不缓存最终提示词。
- **BREAKING**：默认部署仍只有一个应用容器，但依赖外部 MySQL，正常启用外部 Redis 历史缓存；不再把本地目录视为业务数据库。保留私有二维码材料目录、受保护管理端口及内部健康检查，增加外部服务配置、共享实例隔离、备份恢复与故障诊断说明。
- 删除退役的 SQLite/旧单用户运行实现、无调用方法和仅保护退役契约的测试；迁移仍有效的行为测试，保留共享安全能力，将真实联调/验收工具与正式运行包分离。
- 以合成数据比较优化后的 MySQL 直读与 Redis 热缓存，分别报告历史加载、数据库读取量和整轮响应；不预先承诺加速倍数或模型 token 优惠。

## Capabilities

### New Capabilities

- `mysql-managed-persistence`: 全新 MySQL 业务布局、事务与唯一性、单实例所有权、范围化历史查询、重启恢复及旧数据无修改边界。
- `conversation-history-cache`: Redis 有界近期历史、送达后增量更新、版本与授权校验、故障降级和真实性能指标。
- `conversation-time-context`: 可信且可测试的动态时间上下文、重试快照、时区和预算/前缀边界。
- `managed-container-deployment`: 复用 NAS 外部服务的单应用容器配置、专用资源与秘密保护、新安装和备份恢复验收。沿用已有 change 的能力路径，在此声明新的目标部署契约。
- `runtime-simplification`: 退役 SQLite 与旧单用户入口、分离诊断工具、以行为覆盖为依据清理测试和构建路径。

### Modified Capabilities

无。创建时 `openspec/specs/` 尚无主规格；既有多用户要求位于 `add-multi-user-wechat-admin` 的 delta specs，不能把未同步的草案伪装成可直接修改的主规格。上列内容均使用 ADDED delta；后续归档/同步必须协调重叠能力，不能同时保留互斥的“仅本地 SQLite、无 Redis”部署前提。

## Impact

- 基于当前已实现的多用户代码，主要影响 `managed/persistence`、`ManagedAdminConfiguration`、`ManagedTurnWorker`、`RuntimeManager`、`ContextBudget`、配置资源、Maven 依赖、Dockerfile、Compose、CI、探针和测试。使用 JDBC/MySQL 驱动、连接池与 Redis 客户端，具体兼容版本在实施前核实并固定，不将“基本最新版”当作精确版本或升级授权。
- 管理页面既有业务接口和微信协议授权规则不主动扩展；不增加聊天正文浏览、自助注册、每用户模型、分布式任务队列或多应用实例。数据库换型不能自动解锁多实例部署。
- MySQL 使用专用 schema/账号，Redis 使用专用访问权限和项目/安装命名空间；不改 NAS 共享实例全局配置，不使用清库或清全缓存命令。Redis 会额外持有聊天正文副本，其访问与过期策略需进入运维说明。
- 本 change 替换原多用户 change 的 SQLite/本地业务备份前提，延续其身份隔离、30 分钟默认会话空闲边界、已确认投递历史、真实用量和认证要求；不编辑、归档或代为勾选旧 change，其未完成的真实端到端、容器及 NAS 验收仍需按新架构重验。
- 本次请求只创建规划产物，不连接 NAS、不建立真实 schema、不扫码、不调用付费模型、不删除数据、不发布镜像。
