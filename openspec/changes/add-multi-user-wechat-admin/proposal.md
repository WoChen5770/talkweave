## Why

当前程序只支持一套微信登录状态，首次使用需要从文件取二维码、发送绑定口令并手工修改配置，不适合管理员为多个微信用户开通独立机器人。需要提供单容器管理端、可信的扫码自动绑定与多用户会话隔离，并通过可配置的空闲超时和可观测的模型输入缓存降低长对话的使用与运维成本。

## What Changes

- 新增中文管理端：单管理员登录，新增、停用、恢复用户，展示独立绑定二维码、必要的配对码输入、连接状态、重新绑定、全局设置和用量统计；不开放自助注册或聊天正文查询。
- 一个系统用户对应一个微信用户和一套独立机器人连接；管理员创建短时、一次性的绑定任务，用户扫码确认后，在扫码身份与消息身份存在可靠关联的前提下自动授权、持久化并立即生效，无须发送口令、修改 YAML 或重启。
- 将扫码身份关联、两账号连接并存及重复扫码行为的真实验证设为扫码自动绑定验收前置条件。身份不能确认时关闭授权，不使用“首个发消息的人就是主人”的替代逻辑。
- 将连接凭据、轮询游标、登录代次、处理队列、会话、历史及应用侧缓存标识按用户和绑定隔离；支持用户间有界并发，保留同用户顺序、去重、停机恢复及不确定投递保护。
- 新增全局会话空闲超时，默认 30 分钟，管理员保存后无需重启；以有效新用户消息的接收时间计算，超时后的消息创建新会话，不读取旧会话上下文，不删除历史，不使微信登录失效；保留 `/new`。
- 保持一套全局、可由管理端更新的模型配置，支持现有 Chat Completions 兼容中转站。默认不发送专用缓存参数，通过稳定前缀改善上游自动缓存机会，记录真实输入、输出和缓存命中用量；缺失信息显示未知，不保证缓存命中、优惠或所有模型兼容。特定厂商显式缓存适配留作后续扩展，不作为本版交付项。
- **BREAKING**：新版本以动态用户/绑定管理替代单组 `bot-id/owner-id`，使用新的多用户数据布局；不自动迁移、清空或覆盖已有单用户数据库。用户已明确不要求旧账号迁移。
- **BREAKING**：从无管理页面变为受认证保护的 Web 服务；前后端打包到一个容器，新增一个管理端口，微信仍主动出站且健康检查不对外公开。Compose 默认以 `0:0` 运行并允许覆盖 UID/GID，说明权限与攻击面风险。

## Capabilities

### New Capabilities

- `admin-console`: 单管理员认证、中文用户管理、绑定交互、全局模型与会话设置、脱敏状态和操作审计。
- `wechat-user-provisioning`: 管理员发起的一次性二维码任务、扫码身份关联、独立机器人分配、绑定/重绑/恢复的安全状态机。
- `multi-user-runtime`: 多用户连接、消息路由与历史隔离、有界并发、凭据保护、停用和重绑时的在途授权检查。
- `conversation-lifecycle`: 用户内会话顺序、默认 30 分钟空闲超时、热更新设置、`/new`、跨重启持久化与历史保留。
- `model-cache-accounting`: 提供商中立的兼容请求、稳定前缀与缓存边界、按用户/会话归属的真实用量和缓存指标。
- `managed-container-deployment`: 单容器管理端、管理员引导、独立新数据目录、端口与运行身份、备份恢复及部署验收。

### Modified Capabilities

无。当前 `openspec/specs/` 为空，既有能力只存在于尚未归档的 `add-personal-wechat-chat-assistant` 中；本 change 不将那份草案视为已生效主规格，也不修改其文件。

## Impact

- 主要影响 `AssistantRuntimeConfiguration`、`AssistantRuntime`、`LoginCoordinator`、`IdentityVerifier`、`ConversationRepository`、`SqliteStore`、`ContextBudget`、`CompatibleChatClient` 及用量返回类型，并新增管理 API、页面资源、身份关联边界和多用户数据库结构。
- 引入 Spring Boot Web/Security 及单管理员会话认证能力；第一版页面采用同源静态资源和轻量 JavaScript，继续 Java 21、SQLite 与一个部署进程，不引入 Redis、消息队列或独立前端服务。
- 新增受认证的管理接口；默认不提供聊天正文浏览、导出、公开绑定链接、每用户独立模型、自助注册、多管理员角色或按金额收费功能。
- 模型 Key 和微信 token 仅在服务端使用，二维码只在管理员会话中展示；用户聊天仍会发送至管理员配置的模型服务或中转站。应用隔离不等同于防御拥有宿主机/数据库访问权的管理员。
- 现有单用户 change 中的“手工绑定、单连接、无管理端”是本轮明确替换的设计前提；本轮只新增当前 change，后续归档不得把两个相互冲突的设计未经协调地同时作为主规格。
- 自动绑定依赖协议验证；缓存优惠依赖中转站/上游能力。用合成测试通过、管理页可用或接口声称兼容替代真实能力验证均不构成本版端到端验收。
