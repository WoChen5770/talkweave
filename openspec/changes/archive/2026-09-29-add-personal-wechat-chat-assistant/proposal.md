## Why

需要一个可长期部署在个人 NAS 上、通过微信进行日常多轮对话的 Java AI 助手，避免依赖完整 OpenClaw 部署或额外的 Python 转发进程。先打通可靠的文字对话闭环，并将微信协议、会话管理和助手处理分离，为未来受控工具调用留出边界，而不是提前建设 Agent 平台。

## What Changes

- 新建 Java 21、Spring Boot 单应用，使用 Java HTTP 客户端直接连接微信 ClawBot / iLink；采用主动长轮询，不依赖公网回调入口。
- 支持单个机器人连接、无交互容器启动、二维码登录、必要的配对码输入、连接状态恢复、退避重试和凭据失效后重新扫码。
- 仅允许显式绑定的个人微信身份使用，支持文字多轮对话、`/new` 新建会话和最小帮助指令。
- 使用 SQLite 保存当前会话、聊天记录、消息处理状态和微信连接状态；按会话顺序处理消息、去重并控制模型上下文长度。
- 接入用户自定义的 `/v1/chat/completions` 兼容 API，可配置基础地址、密钥、模型、系统提示词和调用预算；第一版非流式，不发送工具定义。
- 提供面向 `linux/amd64`（x86-64）和 `linux/arm64` 的 NAS 单实例 Docker / Compose 构建与部署方案、持久化挂载、凭据保护、无桌面登录材料、健康状态和备份恢复说明；具体 NAS 型号不作为业务实现前置条件。
- 通过 GitHub Actions 测试并构建 amd64/arm64 镜像，检查两种运行时的 Java/SQLite 持久读写后发布到 GHCR；PR 只验证、不发布，不使用真实微信或模型密钥。本机 Docker 不作为继续开发的前置条件。
- NAS 部署、目录授权、真实出网和端到端验收由操作者自行完成；分别记录代码交付、CI 验证和操作者验收状态，不将待验收项提前标为完成。
- 将真实微信收发及实际自定义 API 的兼容性验证放在实施前段，未验证的服务端行为不得视作既有保证。

## Capabilities

### New Capabilities

- `wechat-channel`: 微信机器人登录、单账号连接、文字收发、轮询游标、业务错误处理与断线恢复。
- `personal-conversation`: 个人身份限制、会话生命周期、历史持久化、上下文选择、消息顺序与重复处理保护。
- `compatible-chat-model`: 可配置的 Chat Completions 兼容模型调用、响应提取、上下文预算及失败处理。
- `nas-container-runtime`: NAS 容器运行、持久化目录、无交互登录运维、敏感信息保护及可恢复部署。

### Modified Capabilities

无。当前项目没有已有业务规格或实现。

## Impact

- 新增应用工程、测试、数据库初始化与迁移、容器构建和部署文档；无现有业务接口的破坏性变更。
- 引入 Spring Boot、兼容版本的 Spring AI、SQLite JDBC 及 Java HTTP / 二维码处理所需依赖。具体版本在兼容性验证后锁定，不预设“最新版”。
- 外部依赖为微信 ClawBot / iLink 与用户指定模型服务；账号和模型互通前置验证，amd64/arm64 的 Java 与 SQLite 原生库兼容性在容器化阶段分别验证，NAS 出网与挂载条件在部署阶段核对。
- 聊天内容会发送到配置的模型服务；本地会保存聊天记录及敏感微信状态，需挂载受保护目录并实施备份与日志脱敏。
- 不部署 Redis、独立消息队列、向量数据库或额外 Python 服务。

## Non-goals

- 不接管个人微信的全部好友聊天、通讯录或群聊，仅处理 ClawBot / iLink 通道支持的个人文字对话。
- 不支持多租户、多机器人、媒体理解、知识库、长期记忆、管理后台或公网管理接口。
- 不执行工具、命令、定时任务或多 Agent 工作流；未来工具执行的权限、确认及审计另立变更。
- 不承诺外部 API 的严格 exactly-once 投递、固定 token 有效期、完整兼容所有标称兼容服务或适配全部 CPU 架构；首版仅以 Linux amd64/arm64 为目标，不包含 32 位 x86、arm/v7 或其他平台，也不将构建支持等同于已通过运行验收。
