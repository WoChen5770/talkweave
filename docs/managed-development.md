# 多用户管理端：开发进度与本地预览

> 本轮是实施中的开发版本，不是多微信管理端的完整可部署交付。不要替换现有生产容器，不要挂载原来的数据目录。没有执行真实微信/付费模型调用，也没有迁移旧账号。

## 已实现的组件

- 新多用户 SQLite 布局、只读旧布局拒绝、进程锁、短事务、用户/绑定/会话/消息范围和去重。
- 同源中文管理页：管理员登录/退出、用户新增/停用/恢复、独立二维码弹窗、模型设置、会话空闲超时设置、用户详情、按用户/会话/时间范围用量与分页操作审计。
- 单管理员 BCrypt 哈希、首次初始化不覆盖、CSRF 与来源校验、每分钟最多 5 次登录尝试、30 分钟管理会话、敏感响应 no-store。缺少初始密码时没有可登录管理员。
- 每用户 8 分钟二维码任务：最多 16 个同时有效任务、独立微信 HTTP 客户端、4 个有界网络工作线程；创建/状态/图片/配对码/刷新/取消接口均受管理认证保护。二维码只保留于私有任务目录，状态/审计不含 token、二维码内容或配对码。
- 二维码弹窗按任务 ID 和授权版本操作；旧标签页不能覆盖新任务。关闭/退出/失效释放图片引用，成功/取消/过期/重启清理服务端材料；微信重复要求配对时允许重新输入。
- 模型 Key 不读回；省略 Key 保留旧值，显式空值无效；模型配置保留版本快照。
- 接收事务固定会话归属：默认 30 分钟，1–1440 分钟动态设置，/new 与超时不删除历史、不注销微信。
- 默认不发送专用缓存字段；稳定系统提示词与历史顺序；上下文预算优先于缓存优化。
- 有界原始响应解析，保留输入/输出/缓存输入的真实可空计数，逐次尝试用量归属、幂等入库、按用户/会话/时间统计。未知不等于 0，不计算无依据的节省金额。
- RuntimeManager/ChannelRuntime 已接入 managed profile：独立客户端、接收循环、凭据/游标恢复和退避；共享公平调度器按用户串行、跨用户有界并行。
- 全局模型客户端按不可变配置版本复用，以租约保留旧版本在途请求。停用只取消对应用户，不关闭其他用户的客户端或共享模型池。
- 停用推进授权 epoch；恢复可继续使用未判失效的原凭据，原在途工作不能复活。凭据失效只撤销对应连接，必须由原微信身份重新认证；明确重绑隔离旧历史。
- 回复发送、辅助输入状态调用和长轮询结果入库前再次核对范围；不确定模型/发送不自动重放，已知用量保留原范围。
- 管理页显示每用户连接状态、最近活动与脱敏错误，/api/admin/runtime 提供受认证的全局容量/数据库/低磁盘诊断。内部回环健康端点将单用户微信/模型故障与全局健康分离。
- 两账号协议观察工具与默认失败关闭的身份解析接口，见 [协议验证说明](multi-user-protocol.md)。

## 尚未完成的运行链路

1. 已验证的生产扫码身份映射；目前生产 resolver 始终返回未验证，不存在绕过开关。
2. 默认容器入口切换、受限端口、完整 8 秒退出预算与 root/non-root/双架构镜像验证。
3. 完整多账号浏览器开通/对话流程和 NAS 备份恢复验收。

管理页面的“真实扫码授权尚未开放”是实际能力限制。运行链路已接入，但生产身份映射仍未通过验证。仅新增用户不会请求真实二维码，保存模型不会触发付费测试。**正式 managed 预览中点击“绑定微信”会向微信申请真实二维码，但因身份映射未验证，最终会拒绝授权；这不代表真实扫码开通已通过验收。** 日常开发请使用下面的合成入口，不要扫码试验真实账号。

## 仅用于开发的预览方式

需要 Java 21 与 Maven。构建：

```shell
mvn test package
node --test src/test/js/binding-ui.test.cjs src/test/js/admin-details-ui.test.cjs
```

设置当前进程环境变量，再显式启用 managed profile：

- SPRING_PROFILES_ACTIVE=managed
- MANAGED_DATA_DIR=一个全新的本地目录（默认 ./data-managed）
- ADMIN_INITIAL_USERNAME=自行选定的管理员名（未指定时为 admin）
- ADMIN_INITIAL_PASSWORD=自行生成的强密码（12–72 个 UTF-8 字节，不含控制字符）
- ADMIN_ADDRESS=127.0.0.1（默认仅回环）
- ADMIN_PORT=8080

```shell
java -jar target/talkweave-0.1.0-SNAPSHOT.jar
```

访问 http://127.0.0.1:8080/ 。首次创建管理员后，从后续启动环境中移除初始密码；已持久化哈希不会被残留环境变量覆盖。不要把真实密码写进仓库、命令历史、截图或工单。

预览入口只在 managed profile 下启用；旧单用户配置在该 profile 下不加载。当前默认启动和 Compose 尚未改为多用户，以免破坏已有部署。最终交付前需要移除这段过渡入口安排，不同时保留绕过管理授权的旧运行路径。

**不要直接发布公网端口。** 当前不信任转发头，默认仅回环；反向代理、TLS 与来源校验的部署配置需在后续容器任务中联调。ADMIN_COOKIE_SECURE=true 仅可用于实际 HTTPS 入口，否则浏览器不会发送会话 cookie。

## 数据与恢复

- 不把已有 assistant.sqlite、login/ 或旧目录改名冒充新布局，不删除它们来消除启动拒绝。
- 所有测试/预览使用新目录，原始业务数据不参与测试。
- 备份应停止对应进程后复制完整数据目录，保留权限；不要在 WAL 活跃写入时只复制主数据库。
- 新数据库只由匹配版本的新程序打开；回滚旧程序时使用原旧目录，不能用旧程序打开新库。
- 以上是开发注意事项，不代表已完成容器或目标 NAS 的备份恢复验收。

## 验证与后续顺序

测试范围与真实验收差异见 [场景覆盖表](managed-verification.md)。继续顺序建议：容器退出预算和部署验证 → 经授权的两账号协议验证 → 生产身份适配 → 容器与端到端验收。

普通单元/集成测试必须保持仅本地合成数据；真实扫码需操作者现场授权，不能用合成 VerifiedIdentity 作为生产授权能力。

## 无网络的二维码页面测试

测试类 `ManagedBrowserFixture` 仅存在于 test-classes，必须从测试类路径显式运行其 main 方法；它启用专属 synthetic-browser-only 测试 profile，不会被普通 managed 测试启动加载，也不会打入正式 jar。它替换二维码与消息连接网络端口（消息端不产生入站事件且拒绝发送），**不替换生产身份解析器**。

- 用全新测试目录和虚构管理员密码，监听回环端口，例如 18080。
- 创建两个测试用户；二维码内容明确为 SYNTHETIC-ONLY-NOT-A-WECHAT-LOGIN，不是可登录二维码。
- 合成状态自动进入配对挑战；输入虚构数字后模拟确认登录，生产解析器仍返回“无法确认身份，未授予权限”。
- 验证两个标签页旧版本冲突、两个用户不同任务、刷新、取消、退出后认证失败、图片移除以及 HTML 备注按文本显示。
- Node 前端回归测试直接执行页面中的绑定逻辑，用合成 DOM/延迟响应覆盖过期、跨用户迟到图片、旧轮询覆盖、配对重输与引用清理；不将其等同于真实浏览器或协议验收。

## 运行资源和故障恢复

服务配置（不是管理员页面上的模型参数）：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| managed.runtime.concurrency | 4 | 同时执行的用户业务阶段上限 |
| managed.runtime.per-user-backlog | 1000 | 每用户持久待处理消息上限 |
| managed.runtime.total-backlog | 10000 | 全局持久待处理消息上限 |
| managed.runtime.max-connections | 100 | 同时加载的微信连接上限 |
| managed.runtime.min-free-bytes | 104857600 | 低于磁盘余量时暂停新增接收 |
| managed.runtime.reply-bytes | 4096 | 文字回复格式化字节预算 |

- 全局满载暂停新增接收，但继续排空已接受工作；单用户满载不阻止其他有配额的用户。批次写入超出余量时保留批次、不提交游标，容量释放后重新尝试入库而不重做模型调用。
- 数据库故障或未知 worker 异常将该用户显示为处理中断；不自动重跑可能已计费的阶段。检查并恢复存储后可由管理员停用/恢复或重新认证重新加载连接。重新认证不会改变所有者。
- managed profile 的内部健康端口默认 127.0.0.1:8081，可通过 HEALTH_PORT 改端口。/health/live 不因一个用户待扫码、模型失败或低磁盘而失败；/health/ready 会报告全局数据库、低磁盘和容量问题，不含用户或凭据。不要对外发布该端口。
- 当前测试已验证运行管理器关闭时中断本机工作，但整应用含 Web/二维码/数据库的 8 秒退出预算及默认容器停止验收仍属于待办，不能将组件关闭等同于完整停机验收。

## 用户详情与真实结构合成用量验证

- 用户列表点击“详情与用量”可查看启用、绑定、连接、创建时间与最近有效消息。页面和 API 都不返回聊天正文、附件、账号 sender、token 或模型 Key。停用/恢复和更换身份仍要求确认。
- 会话下拉框按创建顺序每次加载 50 条，显示绑定版本；历史身份仅供管理员追溯元数据和用量，不用于新身份的聊天上下文。
- 筛选时间使用浏览器本机时区输入，转换为 UTC 毫秒；统计依据模型尝试开始时间，开始包含、结束不包含，空白表示不限。
- “未报告”和“异常”属于“不完整”统计的子集，不应相加。已知输入/输出/缓存输入只对有效字段求和；命中率仅覆盖同时有有效 input/cached 且数据状态非异常的尝试，分母为 0 时显示未知。没有统计不代表没有费用。
- 审计可按用户筛选，包含该用户的绑定任务事件；支持继续读取更早操作。详情、用量与审计请求使用取消和序号校验，旧请求不能覆盖新用户/筛选结果，退出后清空内容。
- 显式测试 main 可追加 `--synthetic.seed-usage=true`，仅在新空测试目录中使用 AdminUsageFixture 和真实 repository 写入两个合成用户、不同会话及已知/未知/异常/显式零用量；两用户初始化为停用，不发送消息。该参数不是生产 profile 的功能，不改变生产 resolver。
- 本轮浏览器验证 A 共 4 次尝试、已知输入 2020、缓存 1500、部分统计与覆盖率 75%；B 独立为输入 999、缓存 0。单独筛选未知调用显示未知，显式零显示 0，异常调用不伪造比例。验证时间边界、无效范围、文本注入、用户审计筛选与退出清理。
- 合成浏览器截图位于 .build-cache/admin-details-preview.png 和 .build-cache/admin-usage-preview.png；预览进程已停止，数据仅为开发测试，不是实际微信或上游缓存证明。
