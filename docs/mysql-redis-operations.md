# MySQL / Redis 部署与恢复

适用 `adopt-mysql-redis-conversation-runtime`。CI 在构建、测试和双架构离线检查通过后正式发布：`main` 更新 `latest`，`v*` 标签发布对应版本，每次同时发布 `sha-<完整提交>`。NAS 验收由操作者部署后继续，不再阻止镜像发布；发布不等于完整部署验收。本机合成浏览器、在途关闭预算和历史性能矩阵，以及 CI 两架构产物/root 与非 root 材料检查已验；双架构外部服务运行、独立 CI 外部集成、真实账号与备份恢复仍待验。当前证据与未完成项见 [实施记录](../openspec/changes/adopt-mysql-redis-conversation-runtime/implementation-status.md)。

## 专用资源与权限

只运行一个应用实例，直连操作者已有的 MySQL 和可选 Redis。Compose 不创建数据库容器，不创建数据库或账号，不升级共享服务。MySQL 是唯一业务真源；Redis 只持有可丢弃的聊天历史副本，不能授权、记账或替代数据库。

- 由数据库管理员事先准备专用 schema 和只限该 schema、指定应用来源的账号。首次安装必须为空；不能把其他应用或已承载真实业务的库当测试夹具。
- 日常 READY V2 路径需要该 schema 的 `SELECT`、`INSERT`、`UPDATE`、`DELETE`。初始化/已识别升级另需 `CREATE`、`ALTER`、`INDEX`、`REFERENCES`；完成后由管理员收回不再需要的 DDL 权限，下次升级前再显式授予。无需全局管理、`DROP`、创建用户、读取其他 schema 或终止其他会话的权限。权限应在目标服务按实际账号/角色验证，不执行全局授权作为排错手段。
- 独占运行锁由专用物理连接持有，池连接不能承担这个锁。锁连接丢失永久撤销本进程运行权；修复网络后必须重启应用，旧对象不会透明恢复权限。第二实例在初始化/业务恢复之前被拒绝。
- 显式合成 IT 另需该 schema 的 `CREATE TEMPORARY TABLES` 以验证引擎行为；这不是日常运行必需权限。测试不要求管理服务器权限。
- Redis 使用专用 ACL 用户，键模式只允许 `<key-prefix>:*`；逻辑 database 编号不能替代 ACL 隔离。默认前缀 `talkweave`，生产鍵进一步包含安装 ID、随机运行 ID、用户/绑定/会话和模型版本。
- 当前缓存数据命令为 `EVAL`，脚本只调用 `GET`、`STRLEN`、`SET ... PX`、`DEL`；还应按客户端握手授予必要的 `HELLO`、`PING`、`ECHO`、`AUTH`、`SELECT` 和受限 `CLIENT SETNAME/SETINFO`。先在专用账号验证命令范围；不要为解决权限错误授予全部命令或全部键。诊断的版本/TTL 读取权限另行配置，不加入业务账号的全局管理权限。
- 默认 TTL 60 分钟、完整窗口最大 256 KiB；限制值可在模板内调整。数据库历史不会因 Redis 到期删除。Redis 管理员仍可能看到聊天正文，应限制访问和日志；窗口不包含模型 Key、微信 token、管理员会话或最终 Prompt。

以上权限清单来自当前 JDBC/缓存调用点；当前测试账号并非“最小 ACL 已验收”的证明。不要执行 `FLUSHALL`、`FLUSHDB`、`CONFIG SET`、清库、遍历其他项目键或服务级故障注入。

## 新安装与秘密

1. 保存旧镜像摘要、旧配置和原独立数据；不要挂载、改名或删除旧 SQLite、`login/`、旧布局文件。新版本不导入旧管理员、用户或聊天。
2. 在独立部署目录准备当前 `compose.yml`、`.env.example` 和 `config.external-services.example.yml`。复制配置模板为私有 `config/external-services.local.yml`，填写专用 MySQL/Redis 连接；配置目录 `0700`、文件 `0600`，不得提交 Git 或放入镜像。不要展示 `docker compose config`、inspect 或完整环境输出。
3. 准备新的 `materials` 目录，设置为实际运行 UID/GID 所有、`0700`。它仅保存安装标记和短期二维码等私有材料，不是业务数据库备份。Compose 默认 `0:0`；可设置 `ASSISTANT_UID` / `ASSISTANT_GID` 使用专用非 root 身份，配置文件也必须可读。不要使用 `777`、privileged、Docker socket、递归修改共享目录来解决权限问题。缺失挂载源不会自动创建。
4. 在私有 `.env` 配置 `ASSISTANT_HOST_MATERIALS`、`EXTERNAL_SERVICES_CONFIG`、初始管理员用户名及唯一强密码（12–72 个 UTF-8 字节，无控制字符）。模型 Key 后续在受认证管理页面设置，微信身份不能通过手填 YAML 授权。
5. 操作者明确要求无 SSL 时，使用 MySQL `ssl-mode: DISABLED`、Redis `tls: false`；当前示例遵循这一选择。两条链路为明文，只能用于操作者信任的受限网络。代码缺省仍校验证书；若选 TLS，证书错误会失败，不会自动降级、跳过校验或开启公钥自动获取。需要启用 TLS 时先准备受信任 CA/主机名和客户端信任设置。
6. 确认对应提交的 CI 发布成功，建议将 Compose `image` 从滚动 `latest` 固定到该次正式发布的确定摘要（发布 job 的 summary / `published-manifest` 产物可查），再由操作者部署并完成下方 NAS 待验项。不要把旧缓存的 `latest` 当成当前提交。应用会初始化空专用库，或打开精确识别的布局；配置缺失、未知布局、旧材料会提前失败。不要通过删表、删标记或降版本来绕过拒绝。

管理端默认仅发布 `127.0.0.1:8680`，内部健康 8081 不发布。通过 SSH 隧道访问，例如 `ssh -N -L 18680:127.0.0.1:8680 用户@NAS`，再打开 `http://127.0.0.1:18680`。使用受控 HTTPS/VPN 入口时保持 Host/Origin 一致，HTTPS 才设置 `ADMIN_COOKIE_SECURE=true`；不开放任意跨域。

首次登录后移除 `.env` 的 `ADMIN_INIT_PASSWORD` 及旧预览变量 `ADMIN_INITIAL_PASSWORD`，再由操作者重建应用容器移除环境中的秘密。已初始化管理员不会被残留变量重置。新库重新设置模型、开通用户；新增用户和保存模型不会发出真实调用，点击绑定和启用对话会，必须有对应授权。

## 会话、缓存与诊断

模型 Key 不读回，省略 Key 保留已配置值。模型设置按版本保存，在途调用使用原快照。会话空闲默认 30 分钟、可设 1–1440；`/new` 与超时只隔离后续上下文，不删历史或注销微信。每轮动态时间默认 Asia/Shanghai，区分接收与组装时间，同轮重试不重新采样。

同身份重认证保留历史并撤销旧连接代次；明确更换身份使用新绑定，不能继承旧历史。扫码信任范围及真实重扫风险见 [协议记录](multi-user-protocol.md)。旧协议实测不等于新 MySQL 全流程已验收。

`history-cache.enabled: false` 可明确关闭缓存，MySQL 仍然必需。Redis 故障有限回源，不重试模型/发送；MySQL 或运行权故障停止新增业务。`/api/admin/runtime` 是受认证诊断，缓存指标与模型提供商缓存 token 完全分开；未报告 token 仍显示未知。`LOW_DISK` 只指本地材料磁盘，不能代表远端 MySQL 剩余空间。健康活性不因单用户或 Redis 故障失败，就绪反映数据库、运行权及全局资源状态。

正常停止使用 `docker compose stop assistant`，只停止应用、不停止共享数据库或缓存。关闭协调器先撤销本进程运行权并停止新增调度，所有组件共用 6 秒并行清理预算，给 Web/框架保留 2 秒；不再累加每个组件的等待上限。本机不合作在途模型测试在 8 秒内返回，迟到结果被拒绝、重开保持中断/未知；完整浏览器进程退出约 0.82 秒。组件超时或失败会报告固定组件名并保留必要材料锁，不能视为全部清理成功；正式容器 SIGTERM 验收仍未完成。未知模型结果和未知投递不自动重放。

默认 Redis 命令/阶段预算为 100/250ms，已在授权网络进行合成故障与负载测试。热命中避免正文 SQL，但没有稳定整轮性能提升；收紧为 50/150ms 也未产生一致改善，默认值不变。详见 [性能报告](../openspec/changes/adopt-mysql-redis-conversation-runtime/performance.md)，不要把本机合成值当成 NAS SLA 或模型 token 优惠。

## MySQL V1 → V2 与备份恢复

这里的 V1/V2 是 **本 change 的 MySQL 布局**，不是旧 SQLite 的 V1/V2。V001 不改写；V002 只增加会话 BIGINT 分页序号/索引，保留安装 ID、原行和外键。仅完整、摘要精确匹配的 READY V1 在独占锁下升级。先持久标记 INITIALIZING，再执行 DDL，全部完成后置 READY 并推进 epoch。MySQL DDL 不能当成整套事务回滚；中断会拒绝下次启动，保留现场并人工诊断，不盲目重放 ALTER、删表或降版本。

1. 备份或升级前停止唯一应用实例并确认退出，阻止任何其他写入者；不停止共享 MySQL。使用操作者既有数据库备份工具，明确只导出本项目 schema 的结构和数据，不导出共享实例全部数据库/用户。备份账号与日常业务账号分开配置权限。
2. 同时保存镜像摘要、应用提交、MySQL 实际版本、布局版本/安装 ID、时间、UID/GID，以及私有连接/部署配置和必要材料。业务位于 MySQL，复制 `materials` 不能备份管理员、聊天、模型 Key 或用量。备份含敏感信息，应加密、限制读取，不上传仓库或普通测试报告。
3. 恢复需要独立授权和明确安全目标。优先恢复到操作者另行准备、兼容的专用 schema，保留故障原库和配置。不要为演练清空已建立库，不覆盖其他项目。恢复结构、外键、布局标记、运行 epoch 和安装 ID，不能手工伪造 READY 或删除未知工作。
4. 恢复含有效绑定会恢复连接调度。先限制出站，仅允许已授权数据库/缓存和合成端点，核对备份时间、用户/绑定/会话、用量及未完成操作；备份可能落后于微信/模型的实际结果，人工核对后才恢复真实出站。原处理中/发送中按中断或未知分类，不手动改成待发来重试。
5. 每次应用启动产生新的随机缓存运行命名空间；较新 Redis 键不会被恢复后的应用复用，旧键自然到期。无需备份 Redis，也不扫描、清空全库缓存。
6. 验证原管理员不被重置、历史归属和已知/未知用量、分页、未知投递不重放。临时二维码需重新创建；失效微信凭据需原身份重认证。真实恢复和扫码测试尚未执行，不以普通重开代替。
7. 回滚旧 SQLite 部署时先停止新应用，再用原旧镜像与原独立目录/一致备份；旧程序不能打开 MySQL 布局，新业务不会反向合并。重扫可能让旧 token 失效，文件回滚不能恢复远端授权。所有新旧真实数据均保留，删除必须另行决定。
